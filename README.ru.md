# crt-lens

> 🇬🇧 English version — [README.md](README.md).

Расширение для **Freelens**: движок кнопок-плагинов в меню объектов кластера — как
`plugins.yaml` в k9s. Каждая кнопка описана в YAML: своё действие, иконка, набор объектов,
на которых она видна, и свои правила подбора команды.

Кнопка умеет четыре вещи:

| `type` | Что делает |
|---|---|
| `local` | терминал в доке Freelens — тот же, что открывает штатная кнопка Shell |
| `ext` | внешний терминал: SecureCRT, iTerm, kitty, Windows Terminal… — по пресету из `terminals` |
| `url` | ссылку в браузере: логи, дашборд, тикет — что угодно |
| `crt` | устаревший псевдоним `ext` + `terminal: crt`, старые конфиги продолжают работать |

Любая кнопка может быть не только пунктом меню, но и колонкой в списке объектов
(`column: true`) — см. «Колонка в списке».

Своего конфига у расширения нет, пока его не написали: рядом лежит
[`crt-lens.sample.yaml`](crt-lens.sample.yaml) — пример с четырьмя кнопками (**SecureCRT**
через внешний терминал, **Logs**, **Dashboard** и **Debug**), и его же подставляет кнопка
«Defaults» в настройках. Скопируйте его в `~/.freelens/crt-lens.yaml` и правьте под свои
системы: адреса и идентификаторы окружений живут в `vars`, кода они не касаются.

## Установка

У Freelens 1.x и 2.x разный способ загрузки расширений, поэтому сборки две, по ветке на
мажор хоста. Эта ветка — общая база: кода расширения в ней хватает, а сборки нет, её
приносит ветка версии.

| Ветка | Хост |
|---|---|
| [`v2`](../../tree/v2) | Freelens 2.x |
| [`v1`](../../tree/v1) | Freelens 1.x |

```sh
git clone <этот репозиторий> ~/Documents/git/crt-lens
cd ~/Documents/git/crt-lens
git switch v1            # или v2 — по версии своего Freelens
npm install
npm run build

mkdir -p ~/.freelens/extensions
ln -s ~/Documents/git/crt-lens ~/.freelens/extensions/crt-lens
```

Либо `npm pack` и перетащить `.tgz` в `Extensions`. Поле `files` в `package.json` обязательно:
без него `npm pack` берёт `.gitignore` как `.npmignore` и выкидывает `dist/`.

Чем собирается и что даёт хост каждой версии — `BUILD.md` в ветке этой версии.

После установки Freelens нужно перезапустить (Cmd+R в окне обычно достаточно).

Конфиг лежит в `~/.freelens/crt-lens.yaml`; если рядом уже есть `~/.k8slens/crt-lens.yaml` от
прежних версий, используется он — переезжать не обязательно. Там же рядом рабочий каталог
`crt-lens/` с заданиями. Своего файла ещё нет — в редакторе настроек виден
`crt-lens.sample.yaml` из поставки расширения, его достаточно поправить и сохранить.

## Настройки

`Freelens → Preferences → Extensions → crt-lens`. Там YAML, который можно править и прямо в
файле. Под редактором — превью: что за терминалы нашлись, какие кнопки получились и какие
команды или ссылки они соберут для примерных объектов.

```yaml
kubectl_path: kubectl
pod_tab_title: '{{pod}}/{{container}}'
node_tab_title: '{{node}}'
tab_title_max: 32
default_shell: 'clear; (bash || ash || sh)'
default_node_image: docker.io/alpine:3.13
node_namespace: kube-system
icon_font: ''            # шрифт для иконок-глифов (icon: 'text:…')
default_terminal: ''     # пусто — автоопределение по наличию бинаря
```

### Поля кнопки

| Поле | Смысл |
|---|---|
| `id` | идентификатор; кнопки с одинаковым `id` схлопываются в одну (так делается перекрытие под контекст) |
| `name` | подпись пункта и тултип иконки |
| `type` | `local`, `ext`, `url`, `logs` |
| `terminal` | имя пресета из `terminals` — только для `ext` |
| `icon` | имя material-иконки, `svg:<имя или xml>`, `text:<глиф>`; пусто — иконка терминала. Встроенные: `svg:chart` (график — для кнопки логов, в material такого нет), `svg:terminal` |
| `scopes` | где кнопка видна: `containers`, `pods`, `nodes`, `namespaces` или kind |
| `title` | шаблон заголовка вкладки |
| `cmd` | команда для `local` / `ext` |
| `url` | ссылка для `url` |
| `query` | селектор: рендерится в `{{query}}` и url-encoded `{{query_encoded}}` |
| `shell` / `image` | шелл и образ для дефолтных команд |
| `vars` | свои переменные кнопки |
| `confirm` | спросить подтверждение и показать готовую команду |
| `input` | спросить строку перед запуском и подставить её как `{{input}}` |
| `include_stopped` | показывать кнопку и на остановленном поде или контейнере (по умолчанию только на живых) |
| `column` | показывать кнопку ещё и колонкой в списке |
| `rules` | правила подбора всего перечисленного по маскам |

### Scopes

`containers` — пункт с подменю живых контейнеров пода; целью команды становится контейнер,
а клик по самому пункту открывает контейнер из аннотации `kubectl.kubernetes.io/default-container`
(или первый). `pods`, `nodes`, `namespaces` — сам объект. Можно указать любой kind:
`Deployment` (apiVersion подставится из таблицы известных) или явно `apps/v1:MyKind`.

### Живые и мёртвые

По умолчанию кнопка есть только у того, что бежит: в под, который уже остановлен, шеллом не
зайти, поэтому на упавшем поде и на завершённой джобе кнопок со scope `containers` нет.

`include_stopped: true` снимает это ограничение для конкретной кнопки — логи у упавшего пода и
у отработавшей джобы есть, и смотреть их как раз и хочется. Тогда в подменю попадают и
остановленные контейнеры, каждый со своим цветом кирпича (зелёный — бежит, оранжевый —
ждёт, пустой контур — завершён). В примере флаг стоит у `logs` и `mon`, у `shell` и `debug`
— нет.

**`containers` и `pods` вместе** меняют смысл пункта: клик по нему открывает **под целиком**,
а контейнеры остаются в подменю. Так сделаны логи — у пода свой селектор, у контейнера
уточнённый, — и так же ведёт себя иконка в строке списка. Если `pods` не объявлен, всё как
раньше: пункт открывает контейнер по умолчанию.

Новый kind в `scopes` виден после перезагрузки окна: набор kind'ов Freelens читает один раз
при загрузке расширения. Новая кнопка и новое правило подхватываются сразу.

### Как выбирается кнопка и как — значение

Маски `context`, `namespace`, `pod`, `container`, `node`, `object`, `kube_version` (glob: `*`,
`?`, `[0-6]`, `[!x]`) стоят на кнопке, на правиле и на записи `vars`. Совпасть должны все
объявленные; маска, которой у цели нет вовсе (`pod` у ноды), считается несовпавшей.

Значением маски может быть **список — это «или»**:

```yaml
  - id: logs
    namespace: [prod, temporal]   # видно в prod и в temporal, больше нигде
```

Альтернативы — такие же глобы (`pod: ['deploy-*', 'worker-?']`). На специфичность список
влияет по самой слабой альтернативе: `[prod, '*']` считается таким же грубым, как `*`, иначе
он выигрывал бы у честной маски `namespace: prod`.

Маска, у которой негодное значение (словарь, число, пустая строка, пустой список), при разборе
выбрасывается — и кнопка становится видна **везде**. Поэтому про каждый такой случай
валидатор пишет замечание в превью настроек; молча это больше не проходит.

- **кнопка видна**, когда совпали все её маски;
- кнопки с одним `id` схлопываются: выигрывает самая специфичная, при равенстве — нижняя в файле;
- **значения** (`cmd`, `shell`, `image`, `url`, `query`, `terminal`) подбираются независимо друг
  от друга: правило → значение кнопки → дефолт. Среди правил выигрывает самое специфичное,
  при равенстве — верхнее.

Специфичность: вес масок (имя объекта 4, неймспейс 2, контекст и версия по 1) → длина
литеральной части масок → порядок в файле.

### Шаблоны

Подстановки (регистр не важен): `kubectl`, `kubeconfig`, `context`, `namespace`, `pod`,
`container`, `node`, `name`, `kind`, `api_version`, `button`, `platform`, `node_namespace`,
`node_pod`, `image`, `shell`, `shell_quoted`, `overrides`, `kube_version`, `kube_minor`,
`from`, `to`, `query`, `query_encoded`, `input`, `userinput`, `input_quoted` — плюс всё, что
пришло из `vars`.

`shell_quoted` и `overrides` уже экранированы под тот шелл, в котором команда выполнится
(`sh` или `cmd.exe`) — в кавычки их брать не надо. Именами цели (`pod`, `context`, …) через
`vars` подменить нельзя: они перекрывают таблицу намеренно.

`{{kubectl}}` сам по себе шаблон и знает про `{{kube_version}}` / `{{kube_minor}}` — так можно
держать по бинарю kubectl на минорную версию:

```yaml
kubectl_path: '/opt/kubectl/{{kube_minor}}/kubectl'
```

## Запрос строки: `input`

Кнопка может спросить строку перед запуском — например фильтр для логов. Ответ подставляется
как `{{input}}` в `cmd`, `url`, `query` и `title`:

```yaml
  - id: wl-logs
    name: Логи всех подов
    type: local
    scopes: [Deployment, StatefulSet, DaemonSet, Job]
    title: "logs {{name}}"
    input:
      label: "Фильтр — дописывается в конец команды"
      # поле открывается уже заполненным: обычный запуск — это Enter,
      # править надо, только когда нужен другой фильтр
      default: "| grep -i -E 'error|warn'"
      required: false      # true — пустой ответ не принимать
    cmd: >-
      {{kubectl}} --kubeconfig "{{kubeconfig}}" --context {{context}}
      -n {{namespace}} logs {{kind}}/{{name}}
      --all-pods --all-containers --ignore-errors
      --tail=200 --max-log-requests=100 -f {{input}}
```

Короткие формы: `input: true` — просто спросить строку, `input: 'фильтр'` — то же с подписью.

`default` — не серая подсказка, а настоящее значение поля: диалог открывается с готовым
фильтром, обычный запуск — это Enter, править надо только под конкретный случай.

| Подстановка | Что в ней |
|---|---|
| `{{input}}` | ответ как есть |
| `{{userinput}}` | то же значение, другое имя |
| `{{input_quoted}}` | ответ в кавычках того шелла, в котором команда выполнится; пустой ответ не превращается в `''` |

Диалог показывает готовую команду и пересобирает её на каждое нажатие клавиши — видно, куда
именно подставился ответ. Enter в поле — то же, что нажать «Запустить». Отдельный `confirm`
такой кнопке не нужен: запрос ввода и есть подтверждение.

Ответ подставляется как есть, без экранирования, — на то и расчёт: `| grep -i error` в поле
даёт пайп в команде. Если ответ должен быть одним аргументом, берите `{{input_quoted}}`.

Настройки ругаются на обе молчаливые ошибки: `input` есть, а `{{input}}` в шаблонах нет
(ответ спросят и выбросят) и наоборот — `{{input}}` есть, а `input` не задан (подставится
пустая строка).

## Ссылки: `type: url`

Ссылка собирается в два шага: сначала рендерится `query` (если он есть), потом `url`, куда
селектор попадает уже url-encoded как `{{query_encoded}}`. Идентификаторы окружения берутся из
`vars` — списка записей с масками:

```yaml
vars:
  - context: '*'
    set:
      logs_base: https://logs.example.com
      logs_project: demo
      logs_service: my-service

  - context: '*-prod-*'
    set:
      logs_project: prod

buttons:
  - id: logs
    name: Logs
    type: url
    icon: 'svg:chart'
    scopes: [containers, pods, nodes]
    column: true
    query: '{project = "{{logs_project}}", service = "{{logs_service}}", pod = "{{pod}}"}'
    url: '{{logs_base}}/logs?query={{query_encoded}}&from={{from}}&to={{to}}'
    rules:
      - container: '*'
        query: '{project = "{{logs_project}}", service = "{{logs_service}}", pod = "{{pod}}", container = "{{container}}"}'
      - node: '*'
        query: '{project = "{{logs_project}}", service = "{{logs_service}}", node = "{{node}}"}'
```

Маска `container: '*'` здесь и есть способ сказать «а вот когда контейнер выбран — селектор
другой»: маска совпадает только там, где у цели контейнер вообще есть. Писать `container: ''`
бесполезно — пустые значения при разборе выбрасываются.

Каждый ключ `vars` разрешается отдельно: вес масок → длина литеральной части → источник
(`vars` правила > `vars` кнопки > общая таблица) → раньше в файле. То есть общую запись
`context: '*'` можно точечно перекрыть записью на точный контекст, и остальные ключи из
общей при этом никуда не денутся.

Окно по умолчанию — `from: now-1h`, `to: now`; перекрывается своей записью в `vars`.

Контекста нет в `vars` — ссылка получится неполной, и кнопка просто не покажется: лучше так,
чем увести в чужое окружение. Причина видна в превью настроек и в devtools.

Селектор логов по ноде идёт по метке `meta.k8s.node`. Пункт на поде при этом открывает логи
пода целиком (scope `pods`), а подменю — логи выбранного контейнера: за это отвечает правило
с маской `container: '*'`.

## Логи в доке: `type: logs`

Открывает штатный просмотрщик логов Freelens — тот же таб, что даёт кнопка Logs у пода, со
своим поиском, таймстемпами, переносом строк и скачиванием. Отличие в том, что кнопка вешается
и на воркоад: у DaemonSet, StatefulSet и Deployment такого пункта в приложении нет.

```yaml
buttons:
  - id: dock-logs
    name: Логи в доке
    type: logs
    icon: subject
    scopes: [containers, pods, Deployment, StatefulSet, DaemonSet, Job]
    column: true
    include_stopped: true
```

Ни `cmd`, ни `url` такой кнопке не нужны — цель она берёт из самого объекта:

1. Поды ищутся по владельцу. У DaemonSet, StatefulSet, Job и ReplicaSet это сам объект;
   у Deployment поды принадлежат его ReplicaSet, у CronJob — его Job'ам, поэтому для них
   сначала находится промежуточное звено. Сперва спрашивается стор приложения (со списка
   подов он уже загружен), и только если там пусто — кластер.
2. Таб открывается на самом свежем из бегущих подов — на выкате это новая ревизия, а не
   доживающая старая. Живых нет вовсе — открывается самый свежий: логи упавшего пода как раз
   и нужны.
3. Контейнер берётся из цели: у scope `containers` — выбранный в подменю, иначе тот, что
   указан в аннотации `kubectl.kubernetes.io/default-container`, иначе первый.

Дальше работают селекторы самого таба: выпадашка **Pod** показывает всех соседей по владельцу
(для Deployment — поды текущей ревизии), выпадашка **Container** — контейнеры выбранного пода.

Чего эта кнопка не делает: не сливает логи нескольких подов в один поток — это по одному поду
за раз, с переключением в выпадашке. Нужен общий хвост со всех реплик сразу — это `type: local`
с `kubectl logs {{kind}}/{{name}} --all-pods --prefix` (нужен kubectl ≥ 1.32).

`scopes` у такой кнопки — только kind'ы, у которых бывают поды: `Pod` (в том числе как
`containers` и `pods`), `Deployment`, `StatefulSet`, `DaemonSet`, `ReplicaSet`, `Job`,
`CronJob`. На остальное настройки ругаются.

## Внешние терминалы: `type: ext`

Пресет описывает, чем и как открыть вкладку. Это данные, а не код: любой пресет можно
поправить или добавить свой, не трогая расширение. Полный список встроенных — ниже.

```yaml
terminals:
  kitty:
    job: posix                 # posix | cmd | none — формат задания и стиль кавычек
    darwin:
      argv: ["/Applications/kitty.app/Contents/MacOS/kitty", "--title", "{{title}}", "/bin/bash", "{{job}}"]
    linux:
      argv: ["kitty", "--title", "{{title}}", "/bin/bash", "{{job}}"]
  wt:
    job: cmd
    win32:
      argv: ["wt.exe", "-w", "0", "nt", "--title", "{{title}}", "cmd.exe", "/k", "{{job}}"]
```

Подстановки в `argv`: `{{job}}` — путь к файлу задания, `{{title}}` — заголовок вкладки,
`{{command}}` и `{{command_quoted}}` — сама команда. Необязательный `activate` — чем поднять
окно после запуска (нужен там, где терминал не делает этого сам).

Готовые пресеты: `crt`, `terminal` (Terminal.app), `iterm`, `kitty`, `wezterm`, `ghostty`,
`alacritty`, `wt`, `cmd`, `powershell`, `gitbash` — они встроены в расширение и работают без
единой строчки в конфиге.

Все они целиком, с разбором полей, выписаны в [`terminals.sample.yaml`](terminals.sample.yaml)
рядом с расширением: оттуда запись копируется в свой конфиг и правится под себя — путь к
бинарю, аргументы, `activate`. Файл справочный, ни на что не влияет; что он не разъехался с
кодом, проверяет тест. Одноимённый пресет из конфига заменяет встроенный **целиком**, а не
дополняет его по платформам.

**Как выбирается терминал:** `terminal` у кнопки (подбирается правилами, как и `cmd`) →
`default_terminal` → автоопределение: первый пресет, у которого есть секция под текущую
платформу и существует бинарь из `argv[0]`. Явно названный пресет на наличие бинаря не
проверяется — терминал мог быть поставлен в нестандартное место.

### Файл задания

Команда доезжает до терминала файлом: `<рабочий каталог>/jobs/<заголовок>.sh` (или `.cmd`),
права 700, живёт сутки и убирается автоматически. Так её не приходится протаскивать через
кавычки терминала, и так же её находит вкладка SecureCRT, которой в `argv` достаётся только
заголовок. Пресету с `job: none` команда уходит прямо в `argv` через `{{command}}`.

Заголовок одновременно адресует задание, поэтому две цели с одинаковым заголовком (после
подстановок и обрезки по `tab_title_max`) делят один файл. Если такое встретится — разведите
их шаблоном `title`.

### SecureCRT

Пресет `crt` — обычный пресет; всё, что делает его особенным, лежит в
[`examples/securecrt/`](examples/securecrt/) и ставится **один раз руками**: сессия-обёртка и
скрипт, который выполняет задание во вкладке. Кнопка «Write out SecureCRT examples» в настройках
готовит файлы и печатает, что с ними сделать. Подробности и почему нельзя проще —
[examples/securecrt/README.md](examples/securecrt/README.md).

Коротко: нужны сессия `crt-lens` (Local Shell + Use Script File → `open-shell.py`) и включённый
**Single Instance** в Global Options.

## Колонка в списке

`column: true` добавляет кнопку колонкой в список объектов — по колонке на каждый kind из её
`scopes`, правее встроенных. Клик по иконке в строке делает то же, что клик по пункту меню;
для scope `containers` это контейнер по умолчанию. Пункт меню при этом остаётся.

Колонка попадает в меню «настроить колонки» (шестерёнка в шапке таблицы) — там её можно
скрыть. Новая колонка появляется после Cmd+R.

Колонка — точка расширения `kubeObjectListLayoutColumns`, она есть только в нашем форке
Freelens; на обычной сборке поле просто игнорируется, всё остальное работает как раньше.

## Windows

Расширение кроссплатформенное: пути, кавычки и активация окна выбираются по `process.platform`.

- пресеты `wt`, `cmd`, `powershell`, `gitbash` и секция `win32` у `crt` — из коробки;
- файл задания на Windows — `.cmd` (`@echo off` + команда), кавычки — двойные, с удвоением
  `"` и `%`; пресет может попросить и `posix`-задание (так сделано у `gitbash`);
- SecureCRT: путь `C:\Program Files\VanDyke Software\SecureCRT\SecureCRT.exe`, каталог сессий
  `%APPDATA%\VanDyke\Config\Sessions`, скрипт вкладки сам выбирает `call … & exit` вместо `exec`.

**Проверено это пока только на macOS** — на живой Windows-машине запуск ещё не гоняли.

## Совместимость со старым конфигом

- секции `buttons` нет — из старых полей (`name`, `material_icon`, `rules`) собирается одна
  кнопка со `scopes: [containers, nodes]`;
- `type: crt` читается как `ext` + `terminal: crt`;
- `securecrt_path`, `securecrt_args`, `session_name`, `activate_app` больше не настройки, но
  из них собирается пресет `crt` — старый файл работает без правок. Явный пресет `crt` в
  `terminals` важнее.

## Когда кнопок нет

- нет активного кластера — пунктов нет, в devtools предупреждение с префиксом `[crt-lens]`;
- под или контейнер не бежит, а `include_stopped` у кнопки не стоит;
- не совпали маски кнопки;
- нечего открывать: нет команды, нет ссылки (в том числе из-за отсутствующей записи в `vars`),
  нет пресета терминала или у пресета нет секции под текущую платформу;
- колонки нет, хотя `column: true`: сборка без патча колонок, колонку скрыли шестерёнкой, не
  совпала маска `context`/`kube_version` либо нужен Cmd+R.

Всё перечисленное видно в превью в настройках и в devtools.

## Отладка

Положите пустой файл `debug` в рабочий каталог (`~/.freelens/crt-lens/debug`) — и
`open-shell.py` будет писать в `debug.json`, что за вкладку он увидел и какое задание искал.

Ошибки самого расширения — в devtools окна Freelens (`View → Toggle Developer Tools`), префикс
`[crt-lens]`; туда же пишется собранная команда или ссылка.

## Сборка

Сборки в этой ветке нет: она общая для обеих версий Freelens и держит только код
расширения. Команды, контракт хоста и его грабли — в `BUILD.md` ветки своей версии,
[`v1`](../../tree/v1) или [`v2`](../../tree/v2).
