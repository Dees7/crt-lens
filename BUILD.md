# Сборка под Freelens 1.x

Эта ветка добавляет к общей базе ([`main`](../../tree/main)) всё, что делает из неё пакет
для Freelens 1.x, и ничего больше: манифест, `tsconfig.json`, `vite.config.mjs`, дымовую
проверку и один файл деклараций. Код расширения живёт в базе и про версию хоста не знает —
всё, чем 1.x отличается от 2.x, закрыто сборкой.

```sh
npm install
npm run build        # -> dist/renderer.js (стили внутри бандла)
npm test             # vitest: маски, правила, переменные, ссылки, терминалы
npm run type:check   # типы против API расширений 1.10.3
npm run smoke        # сборка + загрузка бандла с подставленным контрактом хоста
```

## Что даёт хост

Формат — CommonJS: загрузчик расширений 1.x зовёт обычный `require()` на файл из поля
`renderer` манифеста. Поэтому в `package.json` нет `"type": "module"`.

Рендерер 1.x собран с `libraryTarget: "global"`, то есть его экспорты лежат прямо на
глобальном объекте: API в `LensExtensions`, рядом `React`, `ReactJsxRuntime`, `Mobx`,
`MobxReact`. Никакого патча хоста для этого не нужно — так 1.x устроен изначально. В бандл
React и mobx не попадают: своя копия React даёт «invalid hook call», своя копия mobx —
молчаливую потерю реактивности.

## Две вещи, которые хост не делает

**Стили.** Соседний с бандлом `style.css` подхватывает только загрузчик 2.x. Здесь CSS-модули
инлайнятся в бандл и вешаются тегом `<style data-crt-lens>` при загрузке, один раз.

**`import.meta.url`.** Общий код ищет по нему каталог расширения, чтобы дотянуться до
примеров конфига рядом с `dist/`. Штатный CommonJS-шим Rollup написан под браузер и резолвит
путь через `document.baseURI` — в рендерере Electron это страница самого приложения, и
расширение искало бы свои файлы внутри Freelens. Сборка подменяет метаданные на `__filename`.

## Типы

`@freelensapp/extensions` 1.10.3 на npm есть, но его `.d.ts` — семь строк реэкспорта из
`@freelensapp/core`, а тот не объявляет `types` в `exports`: без `paths` в `tsconfig.json`
весь API молча становится `any`.

Тип регистрации колонки (`KubeObjectListLayoutColumnRegistration`) приходит из патча форка и
в опубликованных типах отсутствует, поэтому объявлен в
[`types/kube-object-list-layout-column.d.ts`](types/kube-object-list-layout-column.d.ts).
Сборка и тесты его не читают — он нужен только `npm run type:check`.

## Колонки в списке

Точку расширения `kubeObjectListLayoutColumns` даёт патч форка Freelens, в upstream её нет.
На ванильном Freelens 1.x поле класса молча игнорируется: пункты меню и настройки работают,
колонок в строках списка не появляется.
